# Delegation and effort

Default model: `gpt-6.1-sol`; implementation, scans, tests and code review: `medium`. Substantial feature plans, independent plan critiques and coordination audits: `xhigh`. Confirm actual tool support; unavailable requested settings/gates stay explicit Pending. User choices override defaults.

Reproduced bug: fresh medium attempt → fresh high after one concrete fix fails focused verification → fresh xhigh if high also fails. Preserve hypothesis, fix, revision, reproduction and actual failure; additional xhigh failures seek new discriminating evidence. Raising effort alone is not a new hypothesis.

Before spawn give a compact brief: objective/role/profile and why, starting SHA/draft hashes, relevant source links, exact ownership/interfaces/exclusions, acceptance IDs, evidence paths, stop condition and shared-resource lease. Use fresh compact context and explicit model plus effort where tools allow; never silently inherit a higher parent profile. Each worker/reviewer gets a distinct registered worktree and disjoint writes. Worktrees do not isolate devices, services, data or global Git configuration. Root assigns one resource owner, reserves review/fix capacity, inspects actual diffs/results and records disposition. Nested delegation requires root authority/capacity; internal subtasks do not create user-owned chats.

Coach only concrete ambiguity, missing acceptance, conflicting ownership or observed overhead: suggest one better prompt or smallest missing input while continuing independent authorized work. Consult [feedback](FEEDBACK_LOOP.md); agent counts/reports alone are not progress.
